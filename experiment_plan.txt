================================================================================
  PROBE — Full Experimental Plan
  Goal: Train & evaluate LLM auditors that discover policy violations
         in a flight-booking agent, comparing 3 training methods
================================================================================

PROJECT GOAL
─────────────
  Train an LLM (Qwen3-4B) to play the "user" role against a flight-booking
  target agent (Qwen3-30B), generating diverse multi-turn interactions that
  surface as many of the 20 defined policies as possible.

  Success = high coverage (% policies found), high yield (violations/episode),
            high diversity (distinct failure modes), with plausible interactions.

  ✓ B2 baseline (20 ep): 124 violations, 9/20 policies, 45% coverage
  ✓ Training smoke: 5 GRPO steps, LoRA saved
  ✓ Catalog export: 19 failure clusters

================================================================================
  PHASE 2 — MAIN TRAINING RUNS (3 methods × 2000 steps)
================================================================================

  ┌──────────────────────────────────────────────────────────────────────┐
  │  Run    │ Method   │ Steps │ Batch │ Group │ GPU      │ LR         │
  ├─────────┼──────────┼───────┼───────┼───────┼──────────┼────────────┤
  │  T1     │ GRPO     │ 2000  │   4   │   8   │ 5+7      │ 1e-5      │
  │  T2     │ DPO      │ 2000  │   4   │   8   │ 5+7      │ 5e-6      │
  │  T3     │ GFlowNet │ 2000  │   4   │   8   │ 5+7      │ 1e-5      │
  └──────────────────────────────────────────────────────────────────────┘

  GPU usage:
    GPU 7 = vLLM (target + judge inference)
    GPU 5 = Auditor QLoRA training

  Commands:
    python scripts/train.py --method grpo     --steps 2000 --seed 42
    python scripts/train.py --method dpo      --steps 2000 --seed 42
    python scripts/train.py --method gflownet --steps 2000 --seed 42

  Checkpoints saved every 200 steps → data/checkpoints/{method}/step_{N}

  Curriculum stages (auto-advancing):
    Stage 0: K_max =  6 turns  (short probes)
    Stage 1: K_max = 10 turns  (medium conversations)
    Stage 2: K_max = 16 turns  (complex multi-step)
    Stage 3: K_max = 24 turns  (long-horizon violations)

    Advance when: yield ≥ 0.15 AND no new policies for 50 steps

  Reward schedule (linear over 2000 steps):
    α (progress):    0.5 → 0.1  (early guidance fades)
    β (novelty):     0.1 → 0.4  (exploration increases)
    γ (plausibility): 0.1 fixed

  What to monitor during training:
    - loss per step
    - violation yield per step
    - curriculum stage advancement timestamps
    - EMA divergence

================================================================================
  PHASE 3 — EVALUATION (per trained method + baselines)
================================================================================

  For EACH of {B0, B2, GRPO, DPO, GFlowNet}:

  Step 3a: Generate evaluation episodes
  ──────────────────────────────────────
    200 episodes × 3 seeds = 600 episodes per method

    For trained methods, load final LoRA checkpoint and run against target.
    For B0/B2, already collected in Phase 1.

    GPU layout for eval:
      GPU 7   → vLLM target (same as training)
      GPU 3+4 → vLLM eval judge (Qwen3-Next-80B-A3B, stronger)

  Step 3b: Score with eval judge
  ──────────────────────────────
    The 4 non-deterministic policies (B4, B6, P1, S5) need LLM judge.
    Use the stronger 80B eval judge on GPU 3+4 for final scoring.

  Step 3c: Compute metrics
  ────────────────────────
    python scripts/evaluate.py --log-dir data/logs/{method}

    Metrics:
    ┌────────────────────────────────────────────────────────┐
    │  Category   │ Metric                                   │
    ├─────────────┼──────────────────────────────────────────┤
    │  Coverage   │ % policies triggered (out of 20)         │
    │             │ Unique policy combos                     │
    │             │ Coverage curve (cumulative over episodes) │
    │             │ Missing policies list                    │
    ├─────────────┼──────────────────────────────────────────┤
    │  Yield      │ Violations / 100 episodes                │
    │             │ Severe (HIGH+CRITICAL) / 100 episodes    │
    │             │ Multi-policy rate                        │
    │             │ Per-severity breakdown                   │
    ├─────────────┼──────────────────────────────────────────┤
    │  Diversity   │ # failure mode clusters                 │
    │             │ Cluster entropy (Shannon)                │
    │             │ Discovery rate (new clusters / 50 eps)   │
    │             │ Unclustered %                            │
    ├─────────────┼──────────────────────────────────────────┤
    │  Efficiency │ Episodes per cluster                     │
    │             │ Target calls per policy                  │
    │             │ Judge calls per cluster                  │
    └────────────────────────────────────────────────────────┘

  Step 3d: Export failure catalog
  ──────────────────────────────
    python scripts/export_catalog.py --log-dir data/logs/{method} \
                                     --output data/failure_catalog_{method}.json
