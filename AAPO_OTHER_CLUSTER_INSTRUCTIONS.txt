CRITICAL BUG FIX TO APPLY BEFORE ANY EVALUATION
================================================================

The eval_checkpoint.py shipped in the zip has a LoRA loading bug. The saved
adapter file uses keys like `...lora_A.weight` but the live PeftModel expects
`...lora_A.default.weight` (with adapter name). Because we used strict=False
on load_state_dict, EVERY LoRA weight was silently dropped. As a result, all
prior evaluations were on the BASE model, not the trained checkpoints.

Fix is REQUIRED before any evaluation produces meaningful results.

In scripts/eval_checkpoint.py, find this block:

    print(f"Loading LoRA checkpoint from {ckpt_path}")
    from safetensors.torch import load_file as load_safetensors
    state_dict = load_safetensors(str(ckpt_path / "adapter_model.safetensors"))
    auditor.model.load_state_dict(state_dict, strict=False)
    auditor.model.eval()

Replace with:

    print(f"Loading LoRA checkpoint from {ckpt_path}")
    from safetensors.torch import load_file as load_safetensors
    from peft.utils.save_and_load import set_peft_model_state_dict
    state_dict = load_safetensors(str(ckpt_path / "adapter_model.safetensors"))
    load_result = set_peft_model_state_dict(auditor.model, state_dict)
    if hasattr(load_result, "missing_keys"):
        adapter_missing = [k for k in load_result.missing_keys if "lora_" in k]
        if adapter_missing:
            print(f"  ERROR: {len(adapter_missing)} adapter keys missing! "
                  f"First: {adapter_missing[0]}")
    print(f"  -> Loaded {len(state_dict)} adapter tensors")
    auditor.model.eval()

Verify the fix by running an eval on any checkpoint you receive: the script
should print "Loaded 288 adapter tensors" with no missing-key errors. If it
prints fewer than 288 tensors or any missing-key error, do NOT run further
evals until resolved.
